# Engine metrics on the demo dataset

Demo dataset version 1, generated by
`backend/tests/unit/demo/test_engine_metrics.py`.

The engine runs as the pure function it is, month by month, on the same credits and open
receivables the demo loads. Each proposal is compared with the receivables the generator says
each credit pays. Regenerate from `backend/` with
`CONCILIA_WRITE_METRICS=1 uv run pytest tests/unit/demo/test_engine_metrics.py`.

| Measure | Result | SPEC target |
| --- | --- | --- |
| Credits that pay receivables | 336 | — |
| Proposed correctly by rules 1 to 3 (references) | 252 (75.0 %) | at least 70 % |
| Proposed correctly by rules 1 to 6 | 318 (94.6 %) | above 90 % with accepted AI suggestions |
| Wrong proposals | 0 | 0 |

| Dataset case | Rule | What it is | Credits | Proposed correctly |
| --- | --- | --- | --- | --- |
| exact | R1 | One document in the description, exact amount | 204 | 204 |
| several_documents | R2 | Several documents paid by one credit | 18 | 18 |
| rounding | R3 | Referenced document with a small difference | 15 | 15 |
| detraction | R3 | Referenced document with a detraction withheld | 15 | 15 |
| same_customer | R4 | Same customer, several receivables, no reference | 18 | 18 |
| paid_in_parts | R5 | One receivable paid by several credits | 18 | 18 |
| amount_and_date | R6 | Unique amount and date, no reference | 30 | 30 |
| ambiguous | — | Several equally plausible receivables: left to people or the AI | 9 | 0 |
| partial | — | Partial payment: reconciled by hand or from an AI suggestion | 9 | 0 |

Credits that repeat a payment, pay nothing in the books, or are debits are left out: there is
nothing to match them with. Ambiguous credits and partial payments get no proposal on purpose:
R4 to R6 propose only when exactly one combination fits.
